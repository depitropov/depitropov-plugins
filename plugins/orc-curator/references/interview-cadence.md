# Interview cadence

> **Shared policy.** `shape-product` and `shape-tech` cite it. It is policy only: no flow,
> and **none of the questions themselves.** What to ask is the business of each skill. This file is
> only about rhythm and restraint.

Every Curator skill that asks runs in the main session and asks the user directly.

## Two cadences. Do not swap them.

Pick by this test: does an answer change which question comes next?

| Cadence | Use it when | Who |
|---|---|---|
| **Batch of 3–5** | The questions are independent. You explore a space, you do not narrow one. Turn-by-turn questions tire the user, and the time of the user is the limit. | `shape-product`: wide product exploration |
| **One at a time** | Each answer changes which question is worth asking next. A batch would waste most of it. | `shape-tech`, `direction` |

The wrong cadence has a real cost. A batch of dependent questions wastes questions that the first
answer made useless. One independent question at a time tires the user.

## How many to ask

Ask as few as the request needs. A crisp request needs fewer. The count you need is a ceiling, not a quota:
to ask many questions for their own sake is worse than a thin result. If the request answers
everything, ask nothing. Work from what you have and record the real unknowns. Do not guess.

## Rules for both cadences

- **Offer the real options. Say what each one forecloses.** A question that hides the cost of an
  answer gets a preference that the user would not give if they saw the cost.
- **Prefer multiple choice, with a recommended option and a one-line reason.** Let the user type a
  short free answer. Use only free text for open exploration.
- **A deferral is an answer.** "Not now" becomes a recorded open question. Never leave a silent gap.
  Never write a row for the user that they did not give.
- **Never ask what you can read.** If you can infer it from the request or the files, fill it in
  tentatively, show the assumption, and ask only for confirmation.
- **Say why you ask, in one short line.** "The answer decides if this is one feature or three" lets
  the user send you away from a wrong gap.
- **Ask only what changes something you are about to write.** Do not ask about what a later feature
  can change freely. "Social login or stored email and password" changes if the user record owns
  credentials: ask. "Which providers, how to hash, how long a session lasts" a later feature can
  choose freely: do not ask, and do not research it.

## What an answer is for

An answer lands in a durable file in the same session, or it is lost. Do not keep answers in a
transcript that nothing reads. A Q&A log that no skill updates is how documents go bad. Each skill
names its own destination, and it must have one.
